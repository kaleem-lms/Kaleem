# Internationalisation (English and Arabic)

The dashboard ships in English and Arabic, and Arabic is a merge gate. This page is what you
need to add a string, a plural or a route without turning CI red. The baseline is WCAG 2.2 AA,
i18n and full RTL across every repo, not per feature.

## Adding a key

Strings live in two catalogues that must stay twins:

- `dashboard/src/locales/en/common.json`
- `dashboard/src/locales/ar/common.json`

Rules:

1. Add the English and Arabic key in the same commit, at the same path.
2. Put keys under the feature's own top-level key (`billing.*`, `booking.*`). Do not add a
   key to another feature's block; two units editing one block is what produces merge
   conflicts.
3. Indent with tabs, as the files already do.
4. **Merge conflicts in a catalogue are resolved by script, never by hand.** Take the trunk's
   file and re-insert your keys programmatically (parse, set, write back with tab
   indentation). A hand-merged JSON file loses keys silently.
5. New Arabic copy needs the `hg-arabic-review` gate. Do not ship machine-written Arabic as
   final, and do not guess at religious terminology.

`src/locales/parity.test.ts` fails the unit suite when:

| Rule | Fails when |
| --- | --- |
| 1 | a base key exists in one file and not the other |
| 2 | a value is empty or not a string |
| 3 | a plural family lacks a CLDR form (below) |
| 4 | a `{{name}}` placeholder other than `{{count}}` differs between the twins |
| 5 | an Arabic value contains no Arabic letter (English pasted into the Arabic file) |

## Server strings

The API answers in the dashboard's language (ADR-0058). The dashboard sends `Accept-Language`
on every call; the backend translates with gettext, one catalog per app:
`backend/kaleem/<app>/locale/ar/LC_MESSAGES/django.po`.

Writing a message that reaches a user:

```python
from django.utils.translation import gettext as _

raise ValidationError(_("That time is not available for both of you."), field="start_time")
raise ConflictError(_("A comment is at most %(max)s characters.") % {"max": MAX_COMMENT})
```

- Named placeholders only; never an f-string inside `_()`.
- A noun or phrase interpolated into a platform exception uses a context:
  `NotFoundError(pgettext_lazy("error resource", "Session"), session_id)`,
  `PermissionDeniedError(pgettext_lazy("error action", "cancel a session you are not part of"))`,
  `ExternalServiceError(pgettext_lazy("error service", "video"))`.
- Branching text ("cannot be reported" / "cannot be rated") is whole sentences, not a
  participle in a template.
- Clients branch on `error_code`, never on the message. Add a new code only when a client
  needs one, and never rename one.

Adding or changing a message, from the app directory (in the dev container; GNU gettext is
in the image):

```
cd backend/kaleem/<app>
mkdir -p locale          # first catalog for the app only
django-admin makemessages -l ar --no-location --ignore "*/tests/*" --ignore "*/migrations/*"
# write the Arabic msgstr, keep named placeholders identical, clear any "fuzzy" flag
python manage.py compilemessages
```

`django-admin` needs no project settings for this. `.mo` files are build output and are
gitignored; the image builds them, and the test session compiles stale ones.

Three tests keep this honest, and each fails with the file to fix:

| Test | Fails when |
| --- | --- |
| `tests/test_translation_catalogs.py` | an app calls gettext with no `ar` catalog; a catalog has an empty or fuzzy entry; a message in the source is missing from the catalog |
| `tests/test_error_messages_are_translatable.py` | a platform exception or `serializers.ValidationError` is raised with a message that is not a gettext call; a function binds `_` and calls `_()` |
| the app's own `test_*server_strings*` / API tests | a response does not change language under `Accept-Language: ar` |

New Arabic `msgstr` needs the `hg-arabic-review` gate like any other Arabic copy. Subject
names are religious terms: leave a `# Translators:` note and do not guess.

## Plurals

i18next picks a form by suffix from `Intl.PluralRules`:

- English has `_one` and `_other`.
- **Arabic has six: `_zero`, `_one`, `_two`, `_few`, `_many`, `_other`.** Write all six.

A missing Arabic form is not a visible gap. i18next falls back to English for that one count,
so an Arabic page shows an English sentence only when the count is, say, 0. Nothing at
screen level will hit that by accident. The parity test exists for this.

Arabic `_one` and `_two` may leave out `{{count}}` because the word states the number.

Five families still lack an Arabic `_zero` and sit on `ZERO_FORM_ALLOWLIST` in the parity
test. The list can only shrink; raising its ceiling needs an ADR.

## Placeholders

Interpolate with `{{name}}`. Keep the same names in both languages; only `{{count}}` may be
dropped, and only in Arabic. Never build a sentence by joining translated fragments, because
word order differs.

## Layout in RTL

- Use logical properties and utilities: `ms-*`, `me-*`, `ps-*`, `pe-*`, `start-*`, `end-*`,
  `text-start`, `text-end` (this has broken Arabic before; check it), `border-s`, `rounded-s`.
  Not `ml-*`, `pr-*`, `left-*`, `text-left`.
- Icons that point somewhere (chevrons, arrows, back) must mirror in RTL. Icons that do not
  (a clock, a check) must not.
- Numbers, times and dates go through the locale-aware formatters, not raw `toString`.
- Test in both directions at 320px and 1280px.

## The Arabic sweep and its lists

`dashboard/e2e/arabic-sweep.spec.ts` visits every authed route in Arabic, as the account that
sees its real content, and checks:

| Check | Passes when |
| --- | --- |
| `dir` | `<html dir="rtl" lang="ar">` |
| `reflow-320`, `reflow-1280` | no sideways scroll; a failure names the widest element |
| `axe-light`, `axe-dark` | no WCAG 2.2 AA violation, and `color-contrast` was actually evaluated |

Not covered: the call room, raw unlocalised times, directional-icon mirroring, Arabic-Indic
digits, server text beyond the two e2e flows in `server-strings.spec.ts`, and any browser but Chromium.

### Route lists

Routes are listed per area in `dashboard/e2e/routes/<area>.ts` (`{ path, as }`, where `as` is
the seeded account). A page that several roles see differently appears once per role, because
pages gate by role in the component, not the route. `e2e/routes/index.ts` joins them into
`AUTHED_ROUTES`; the English `reflow.spec.ts` reads the same list.

**Adding an authed route (a file under `src/routes/_authed/`) without a list entry fails CI**,
naming the route file. Add the entry, or put it in `NOT_SWEPT` with a reason.

### Allowlists are shrink-only

Known failures are in `e2e/arabic-sweep.allowlist.ts`, one entry each with the ISSUES.md entry
that tracks it.

- An allowlisted check still runs. If it passes, CI fails with "stale allowlist entry".
- The fix PR deletes the entry **and lowers `ALLOWLIST_CEILING`** in the same diff.
- Raising the ceiling is a gate decrease and needs an ADR, as with the coverage floors
  (ADR-0026).

### Time budget

The whole `pnpm e2e` step has a 9-minute `globalTimeout` in CI, under the 15-minute job kill so
a red run is a failure, not a cancellation, and still uploads its `test-results/`, HTML report and logs (verified: the report is written on a global timeout when the config reporters apply; `--reporter=list` on the command line overrides them and writes none). Crossing it means the suite should be sharded by area
(a matrix job with one Postgres per shard, grouped like the route lists). That is its own
unit. Raising the budget needs an ADR.
